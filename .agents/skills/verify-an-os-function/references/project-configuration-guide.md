# 工程配置指南

配置 trial、增补共享定义、复用 annotated C 或调整库路径时参考本指南。

## Trial 与全局库

每个 trial 根目录的 `_CoqProject` 列出本次使用的外部 `-R`/`-Q` 路径、全局库和本地实验库。本地实验库按主 skill 的 [文件组织与存放](../SKILL.md#文件组织与存放)统一映射 `trial/lib/`，只包含需要修改的共享库文件副本及新增库文件；未修改的依赖直接从全局库导入，不复制整个依赖闭包。全局库与本地实验库使用不同的逻辑前缀，避免同名模块相互遮蔽；依赖实验副本时使用本地逻辑路径，仍直接复用的共享模块使用全局逻辑路径。若依赖者必须调整 imports、类型或接口才能使用修改版，将这些需要修改的文件纳入 trial，避免在同一依赖链中混用不兼容的全局原版与 trial 修改版。路径映射与 Makefile、QCP 命令及 `Require` 使用的逻辑名称保持一致；相对路径按对应项目的工作目录解析。

CRTOS 全局库由 `/home/xinra/crtos/_CoqProject` 管理。现有映射为 `-R ./lib CRTOS_Verify.lib`，外部依赖也在该文件中声明。沿用此组织，不另在 `lib/` 内维护一份重复配置。

Trial 不会因为位于 CRTOS 根目录下就自动继承根 `_CoqProject`，使用全局库时仍需显式配置映射及所需外部依赖。路径变化后同步构建、QCP 和编辑器配置，并重新编译受影响的 `.vo`。

上述组织与外部库引用规则在 implement 阶段继续适用，必须[沿用现有 trial 工程](implementation-and-validation-guide.md#沿用现有工程)进行验证。由 QCP 工具侧适配本 OS 工程的格式与外部库引用，不因工具默认约定而重新配置、复制整套依赖或重组工程。

## 共享库的增量维护

### 已有共享库的复用与修改

`/home/xinra/crtos/lib/` 中的已有定义应优先复用，也允许按当前源码和验证需求增补或修改。已有接口缺少所需元素、操作或引理时，在职责对应的模块中增量补充；已有定义不符合当前 C 或本 skill 的要求时，说明定义位置、修改依据和影响后修正，不另起一套重复概念。

无需修改的文件直接从全局库导入。需要修改的文件先复制到 `trial/lib/`，记录全局来源和可比较的基线版本，在副本中修改；新增库文件也放在 `trial/lib/`。若依赖者必须调整 imports、类型或接口才能使用修改版，只将这些需要修改的文件一并纳入 trial。设计和审阅期间不写回或移动全局原文件，不复制整套库或整个依赖闭包。

共享库的修改可以涉及定义含义或接口，但必须符合真实源码与系统协议，并同步调整受影响的构造、操作、predicate、spec 和证明。若修改导致已有审阅或证明结论不再适用，明确其影响并重新审阅受影响部分，不沿用失效结论。修改已有文件时检查修改处及受影响内容，新建文件时检查完整文件。共享库的修改权限不允许间接改变复用 spec 的原语义；涉及已有 spec 时仍须满足下文的语义保持规则。

### 审阅后合并共享库

按主 skill 的[审阅后自动合并库](../SKILL.md#审阅后自动合并库)执行：设计和审阅期间只修改 trial 副本及新增文件；复制时记录全局来源和可用于比较的基线版本。在完整验证流程中，predicate 和 spec 均 `review-passed` 后，main agent 主动合并本次修改及新增的库文件，无需另设共享库更新审批，不等到实现证明结束。模块文件和函数专用文件均适用，不要求被多个模块或 trial 使用。

新增模块状态时，在全局状态文件中导入并增加相应字段；新增模块内存表示时，在系统不变量中导入并增加所需的组合项及跨模块关系。导入仅使定义可用，不会自动更新 record 构造、状态更新函数或不变量；这些使用处随接口变化同步调整。仅新增局部引理或操作时，不需要改动全局组合。

合并前检查依赖、名称冲突及目标文件的最新内容，以复制时基线、trial 修改版及全局最新版本比较并合并，不得直接用旧副本覆盖其他工作。共享文件只能依赖共享库或外部库，不能依赖 trial 的实验文件或专属路径；从 trial 引入的必要新依赖应通过审阅后一并纳入全局库。若合并需要改变已审阅定义的含义或接口，先重新审阅受影响部分。

合并后，按实际变化更新已有 `lib/index.md`、根项目和 trial 的 `_CoqProject`、相关 Makefile、QCP 配置、编辑器路径以及使用处的 imports；将当前 trial 对已合并定义的引用切回全局逻辑路径。使用根项目配置重新编译新增或修改的 `.v` 文件及受影响的依赖者，并检查当前 trial 的引用与类型一致性，不沿用 trial 的 `.vo` 作为共享库编译结果。检查通过后才能报告共享库更新完成；语义或接口变化时复查受影响的已有结论。此处检查不提前启动 QCP symbolic、VC 或实现证明。

Trial 中保留此次通过审阅的版本，便于追溯，并记录审阅版本到合并后文件及逻辑路径的对应关系。纯路径迁移且不改变已审阅语义时不要求重新审阅。

## Annotated C 的增量维护

### 已有 spec 的复用与特化

`/home/xinra/crtos/annotated_C/` 中已有的函数 spec 应直接导入 trial 使用。导入时须完成必要的等价适配和依赖配置，确保已有 spec 能用于当前源码、配置和 predicate 接口，同时保持原 contract 的语义；多函数源文件按本 skill 的规则提取为一函数一文件，保留该函数的已有具名 specs 和所需声明。只引入当前闭包需要的内容，不复制整棵 annotated C 目录。设计和审阅期间仅修改 `trial/annotated_C/src/` 中的副本；审阅后的合并规则见下节。

**从根 `annotated_C/` 导入复用已有 spec 的依赖函数，本轮不需要生成其实现的 VC，也不重新证明其函数体。** 将其标记为 `reused-spec` 边界，记录来源文件、spec revision 和采用的 contract；即使 trial 中保留了该函数体，也不因此将它加入本轮实现证明目标。导入后的适用性、类型、源码适配及 caller-local contract 一致性仍须检查，但不以缺少本地 proof 文件为由自动安排重新证明。

仅做等价适配的导入仍适用上述规则；新增或改变语义的 contract 及新增特化的推导义务另行记录，不能当作原 spec 已覆盖。本轮新写后合并到全局目录的 spec 不追认为已有导入 spec；用户明确指定的实现证明目标仍按目标范围执行。

允许在 trial 副本中调整 imports、名字、typedef 或 predicate 表示，但须保持原 contract 的含义、调用范围、返回路径、effect、ownership 和 frame。原 spec 不适用于当前源码或无法等价适配时，说明不匹配及影响，不通过偷偷加强 Require 或弱化 Ensure 继续复用；确需改变原语义时，作为独立的设计变更交由用户决定。

调用场景有额外事实时，可以保留原 spec，并在同一 canonical 文件中新增具名的特化 spec。

例如 semaphore 调用 `KTaskWakeup` 时，若已知目标 task 位于该 semaphore 的等待链表中，可新增具名的 semaphore 场景 spec：将通用 spec 的来源链表参数实例化为该等待链表，并从 semaphore predicate 导出 task 成员关系及调用所需资源。后置状态须由通用 spec 的链表变化和相关 predicate 推导，重新组合 semaphore 的表示与未修改资源；不能把调用前的成员关系原样断言为调用后仍成立。该成员事实也不能代替原 spec 对 task 状态、ID 解析、临界区或其他资源的要求。

审阅时记录特化所依据的原 spec revision、参数对应与推导义务，检查推导在语义上成立。

### 审阅后合并 annotated C

在完整验证流程中，predicate 和 spec 均 `review-passed` 后，与共享库一样主动合并本次等价修改及新增特化到根 `annotated_C/`，无需另设更新审批，不等实现证明结束。比较基线、trial 版本及全局最新版本，按原函数位置增量合并，保留其他工作和原 contract；不以单函数切片覆盖原多函数文件，不把 trial 专属路径写入全局文件。所需新增库依赖一并按共享库规则合并。

合并后核对 imports、具名 spec、受影响的 caller-local contracts 及源码等价性，记录 trial 与全局文件的版本对应；trial 继续保留本次验证的一函数一文件输入。共享 `.v` 依赖按根项目配置编译，annotated C 在此阶段完成人工结构与语义一致性检查，不提前启动 QCP。合并只表示设计已审阅，原有证明状态按实际适用范围保留；导入复用部分按上述 `reused-spec` 规则免于本轮 VC 和函数体重证，新增或受影响的证明义务交给用户确认 revision 后的 `implement`。

## 编辑器适配

项目已有的 Coq 8.18--8.20 / VsRocq 适配说明记录了局部 `_CoqProject` 路径未按文档生效的情况。遇到该环境时，将共享库、当前活动 trial 的外部路径和本地 `lib/` 映射同步到 CRTOS 根 `.vscode/settings.json` 的 `vsrocq.args`，并确保 `"*.v": "rocq"`。

该适配使用已经解析并确认存在的绝对路径，不依赖 `vsrocq.args` 对 `${workspaceFolder}` 的展开。切换活动 trial 时替换旧 trial 专属映射，不累积映射到同一逻辑路径的多个 `lib/`。

Coq/VsRocq 升级后实测局部项目和路径变量是否生效，再决定是否继续使用此适配；不要仅根据 Coq 版本推断编辑器行为。
