# 工程配置指南

配置 trial、增补共享定义或调整库路径时参考本指南。

## Trial 与全局库

每个 trial 根目录的 `_CoqProject` 列出本次使用的外部 `-R`/`-Q` 路径、全局库和本地实验库。本地实验库按主 skill 的 [文件组织与存放](../SKILL.md#文件组织与存放)统一映射 `trial/lib/`，其中同时容纳新增文件和复制的共享库文件。全局库与本地实验库使用不同的逻辑前缀，避免同名模块相互遮蔽；依赖实验副本时使用本地逻辑路径，仍直接复用的共享模块使用全局逻辑路径。路径映射与 Makefile、QCP 命令及 `Require` 使用的逻辑名称保持一致；相对路径按对应项目的工作目录解析。

CRTOS 全局库由 `/home/xinra/crtos/_CoqProject` 管理。现有映射为 `-R ./lib CRTOS_Verify.lib`，外部依赖也在该文件中声明。沿用此组织，不另在 `lib/` 内维护一份重复配置。

Trial 不会因为位于 CRTOS 根目录下就自动继承根 `_CoqProject`，使用全局库时仍需显式配置映射及所需外部依赖。路径变化后同步构建、QCP 和编辑器配置，并重新编译受影响的 `.vo`。

## 共享库的增量维护

按主 skill 的 [文件组织与存放](../SKILL.md#文件组织与存放)，共享定义可以直接在对应模块中增补或修改，无需先复制到 trial。Trial 中的模块文件和函数专用文件，也可以在文件及必要依赖通过对应审阅、编译或类型检查后复制到共享 `lib/`，不要求被多个模块或 trial 使用。不另设一次共享库修改或复制审批。

新增模块状态时，在全局状态文件中导入并增加相应字段；新增模块内存表示时，在系统不变量中导入并增加所需的组合项及跨模块关系。导入仅使定义可用，不会自动更新 record 构造、状态更新函数或不变量；这些使用处随接口变化同步调整。仅新增局部引理或操作时，不需要改动全局组合。

直接修改或复制前检查依赖、名称冲突及目标文件的最新内容，不得覆盖其他工作。复制时如果目标在 trial 设计期间发生变化，先合并并复查受影响部分，再复制通过审阅的版本。共享文件只能依赖共享库或外部库，不能依赖 trial 的实验文件或专属路径；从 trial 引入的必要新依赖应通过审阅后一并复制。

直接修改或复制后，按实际变化更新已有 `lib/index.md`、构建配置以及使用处的 imports。使用根项目配置重新编译新增或修改的 `.v` 文件及受影响的依赖者，不沿用 trial 的 `.vo` 作为共享库编译结果。编译通过后才能报告共享库更新完成；语义或接口变化时复查受影响的已有结论。

Trial 中保留此次通过审阅的版本，便于追溯。接入共享库时确认实际引用版本；留存副本可放在不参与构建的 snapshot 目录，避免与共享定义发生逻辑路径冲突或遮蔽。

## 编辑器适配

项目已有的 Coq 8.18--8.20 / VsRocq 适配说明记录了局部 `_CoqProject` 路径未按文档生效的情况。遇到该环境时，将共享库、当前活动 trial 的外部路径和本地 `lib/` 映射同步到 CRTOS 根 `.vscode/settings.json` 的 `vsrocq.args`，并确保 `"*.v": "rocq"`。

该适配使用已经解析并确认存在的绝对路径，不依赖 `vsrocq.args` 对 `${workspaceFolder}` 的展开。切换活动 trial 时替换旧 trial 专属映射，不累积映射到同一逻辑路径的多个 `lib/`。

Coq/VsRocq 升级后实测局部项目和路径变量是否生效，再决定是否继续使用此适配；不要仅根据 Coq 版本推断编辑器行为。
