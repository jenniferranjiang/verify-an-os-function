
## Processing from Source Code to Verification Slice Code

Source code location: `../crtos`

Verification slice code location: `annotated_C/src/kernel/thread`


The current differences between the verification slice code and the original source code are as follows:

- Comment out printing statements, such as debugging code `KPrint` and `hook` functions;

- Handle complex macro definitions: some complex macro definitions are re-abstracted as functions, and their specifications are provided in the verification unit. For example, `NULL_PARAM_CHECK` is replaced with `NULL_PARAM_CHECK_1`;

- Replace function pointers with the function names of the actual functions pointed to by those pointers;

- When verifying functions called inside a critical section, comment out nested critical section entry/exit operations (lock/unlock operations) inside the called functions.

- The effect of `DO_KTASK_ASSIGN` is to explicitly yield the execution privilege: the higher-priority task is executed first, and later scheduling eventually restores the execution privilege of the previous task and continues execution from the point where it yielded. The current verification logic models the system as preemptive execution, and therefore does not distinguish this explicit yielding behavior. Currently, it is treated as an empty critical-section entry/exit operation and replaced with the function `KTASK_ASSIGN()`. Its specification is declared in the verification slice as follows:

```c
void KTASK_ASSIGN()
/*@ outside_critical
    With (sg : StableGlobalState) (before : VarGlobalState) X
    Require
      safeExec(LastSeen(before), abs_ktask_assign, X) &&
      OutsideCritical(sg, before)
    Ensure
      exists after,
        safeExec(LastSeen(after), return(tt), X) &&
        OutsideCritical(sg, after)
 */;
```

- When verifying functions called outside critical sections, for shared memory accesses outside critical sections, wrap each access statement with a critical section.

When it is unclear how the source code should be transformed in the verification slice to enable verification, first inspect and learn from the transformation methods used in already verified functions. If no applicable example exists, stop and consult the human expert for confirmation.
