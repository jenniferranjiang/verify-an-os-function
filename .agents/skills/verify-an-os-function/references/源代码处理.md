
# 默认源代码处理规则

本文提供 skill 的默认规则。用户可按 [配置说明](../CONFIGURATION.md#用户源码处理规则)通过 `source_processing` 指定自己的规则文件。用户规则与本文冲突时，仅冲突条目以用户规则为准；无冲突的条目共同生效。下文所述处理方式及咨询条件均受此优先级约定约束。

## 从源代码到验证切片代码的处理

源代码位置使用配置的 `source_root`，不从本文件位置推断。

目前，验证切片代码与原始源代码的差异如下：

- 注释掉打印语句，例如调试代码 `KPrint`，以及 `hook` 函数；

- 处理复杂宏定义：将部分复杂宏定义重新抽象为函数，并写出其spec。例如，将 `NULL_PARAM_CHECK` 替换为 `NULL_PARAM_CHECK_1`；宏没有指定处理方式时，就重新抽象为函数。

  例如，源代码中的宏调用：

  ```c
  NULL_PARAM_CHECK(task);
  ```

  在验证切片中替换为已有的检查函数调用：

  ```c
  NULL_PARAM_CHECK_1(task);
  ```

  并在调用者函数定义前提供该检查函数的声明及其 spec：

  ```c
  inline void NULL_PARAM_CHECK_1(void *p)
  /*@
      Require emp
      Ensure p != 0
  */
  ;
  ```

  所有调用点处都可以复用已有的 `NULL_PARAM_CHECK_1` 及其 spec，与对函数的操作类似，不在调用者中重复展开空指针判断和死循环。该 spec 表示：正常返回时，`p` 非空；不保证空指针输入时也会返回。函数声明及 spec 不等于函数体证明，是否复用已有证明或作为 trusted 使用，仍需按相应依据区分。

- 将函数指针替换为其实际指向的函数名；

- 验证在临界区内被调用的函数时，注释掉被调用函数内部嵌套的临界区进入／退出操作（加锁／解锁操作）。

- `DO_KTASK_ASSIGN` 的作用是显式让出执行权：优先执行优先级更高的任务，之后通过调度，最终恢复原任务的执行权，并从让出执行权的位置继续执行。当前验证逻辑将系统建模为抢占式执行，因此不区分这种显式让出执行权的行为。目前，将其视为一次空临界区的进入／退出操作，并替换为函数 `KTASK_ASSIGN()`。其规约在验证切片中声明如下：

```c
void KTASK_ASSIGN()
/*@ outside_critical
    With (sg : StableGlobalState) (before : VarGlobalState) X
    Require
      safeExec(LastSeen(before), abs_ktask_assign, X) &&
      OutsideCritical(sg, before)
    Ensure
      exists after,
        safeExec(LastSeen(after), return(tt), X) &&
        OutsideCritical(sg, after)
 */;
```

- 验证在临界区外被调用的函数时，如果被调用函数（callee）内部直接访问共享内存，应在实际执行该访问的 callee 中加入临界区，不在调用它的 kernel 函数（caller）中包裹该函数调用。例如，`KTaskSuspend` 在临界区外调用 `JudgeKTaskStatIsInit` 时，保持 `KTaskSuspend` 中的调用不变，在 `JudgeKTaskStatIsInit` 内保护对 `task->task_dync_sched_member.stat` 的读取。

  临界区应尽量小。对于只读取一次共享字段并据此计算返回值的函数，推荐在临界区内只把共享字段读入局部变量，退出临界区后再完成掩码、比较和返回。例如：

  ```c
  BOOL JudgeKTaskStatIsInit(KTaskDescriptorType task)
  {
      x_base lock = 0;
      uint8 stat = 0;

      NULL_PARAM_CHECK_1(task);
      lock = CriticalAreaLock();
      stat = task->task_dync_sched_member.stat;
      CriticalAreaUnLock(lock);

      return ((stat & KTASK_STAT_MASK) == KTASK_INIT);
  }
  ```

  这样，临界区只覆盖真正的共享内存访问；局部变量 `stat` 后续的计算不需要持锁。宏常量可以按当前配置展开为对应常量，但这与临界区放置无关。

- 不能把整个模块的函数规约集中放进一个 *_specs.h。

- 不能整目录复制代码；每个需要处理的函数单独放一个文件。

如果不清楚应如何将源代码转换为可供验证的切片代码，应先查看并参考已验证函数所采用的转换方法。如果没有适用的示例，应停止并咨询人类专家以获得确认。
