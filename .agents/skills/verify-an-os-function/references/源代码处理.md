
# 默认源代码处理规则

本文提供 skill 的默认规则。用户可按 [配置说明](../CONFIGURATION.md#用户源码处理规则)通过 `source_processing` 指定自己的规则文件。用户规则与本文冲突时，仅冲突条目以用户规则为准；无冲突的条目共同生效。下文所述处理方式及咨询条件均受此优先级约定约束。

## 从源代码到验证切片代码的处理

原始 OS 源码位置按 workspace 的[路径配置](../CONFIGURATION.md#路径配置)确定。

原始 OS 源码始终只读。以下适配以及经用户批准的 bug 修复都只写入 workspace 的 annotated C 副本。缺陷修复单独按[源码错误报告](reporting-guide.md#源码错误报告)记录原始基线、修复差异与副本 revision，验证结论仅覆盖该修复版本。

目前，验证切片代码与原始源代码的差异如下：

- 注释掉打印语句，例如调试代码 `KPrint`，以及 `hook` 函数；

- `NULL_PARAM_CHECK` 按当前源码和配置下的实际行为处理，不仅凭宏名选择规则：

  - 新版 CRTOS 在空指针时输出调试信息并增加仅用于测试的错误计数，之后继续执行。验证切片中注释掉该宏调用，与 `KPrint` 一样排除调试和测试观测；不为它生成检查函数或 `Ensure p != 0`。本适配不保留调试输出及该测试计数的变化。新代码引入的空指针错误计数不是验证所关心的内容，验证本身就要证明内存访问是安全的，也即，只有caller提供拥有指针指向的内存权限才能做后续的符号执行
  - 旧版 CRTOS 在空指针时进入死循环，阻断后续执行，不能套用上述注释规则。验证旧版时仍可复用 `NULL_PARAM_CHECK_1` 及其 spec，保留“正常返回时指针非空、空指针输入不保证返回”的语义；复用声明不等于已证明函数体，也不自动获得 trusted 授权。

    旧版源码中的调用：

    ```c
    NULL_PARAM_CHECK(task);
    ```

    在验证切片中替换为以下函数，并在调用者函数定义前提供检查函数的声明及其 spec：

    ```c
    inline void NULL_PARAM_CHECK_1(void *p)
    /*@
        Require emp
        Ensure p != 0
    */
    ;
    ```

    所有适用的旧版调用点均可复用该接口，不在调用者中重复展开空指针判断和死循环。
    该 spec 仅表示正常返回时 `p` 非空，不提供指针所指内存的访问权限；不适用于新版仅记录诊断后继续执行的宏。

- 处理复杂宏定义：优先采用本文或用户规则中指定的处理方式。没有指定处理方式的复杂宏可重新抽象为函数，并提供完整 spec，保留实际控制流、返回值及相关副作用。函数声明及 spec 不等于函数体证明，是否复用已有证明或作为 trusted 使用，仍需按相应依据区分。

- 静态函数指针调用按[QCP 工具适配第 1 条](#1-函数指针调用转为直接调用)转换为直接调用；

- 验证在临界区内被调用的函数时，注释掉被调用函数内部嵌套的临界区进入／退出操作（加锁／解锁操作）。

- `DO_KTASK_ASSIGN` 的作用是显式让出执行权：优先执行优先级更高的任务，之后通过调度，最终恢复原任务的执行权，并从让出执行权的位置继续执行。当前验证逻辑将系统建模为抢占式执行，因此不区分这种显式让出执行权的行为。目前，将其视为一次空临界区的进入／退出操作，并替换为函数 `KTASK_ASSIGN()`。其规约在验证切片中声明如下：

```c
void KTASK_ASSIGN()
/*@ outside_critical
    With (sg : StableGlobalState) (before : VarGlobalState) X
    Require
      safeExec(LastSeen(before), abs_ktask_assign, X) &&
      OutsideCritical(sg, before)
    Ensure
      exists after,
        safeExec(LastSeen(after), return(tt), X) &&
        OutsideCritical(sg, after)
 */;
```

- 验证在临界区外被调用的函数时，如果被调用函数（callee）内部直接访问共享内存，应在实际执行该访问的 callee 中加入临界区，不在调用它的 kernel 函数（caller）中包裹该函数调用。例如，`KTaskSuspend` 在临界区外调用 `JudgeKTaskStatIsInit` 时，保持 `KTaskSuspend` 中的调用不变，在 `JudgeKTaskStatIsInit` 内保护对 `task->task_dync_sched_member.stat` 的读取。

  临界区应尽量小。对于只读取一次共享字段并据此计算返回值的函数，推荐在临界区内只把共享字段读入局部变量，退出临界区后再完成掩码、比较和返回。例如：

  ```c
  BOOL JudgeKTaskStatIsInit(KTaskDescriptorType task)
  {
      x_base lock = 0;
      uint8 stat = 0;

      /* NULL_PARAM_CHECK(task); 新版仅记录调试信息和测试计数，按上述规则省略。 */
      lock = CriticalAreaLock();
      stat = task->task_dync_sched_member.stat;
      CriticalAreaUnLock(lock);

      return ((stat & KTASK_STAT_MASK) == KTASK_INIT);
  }
  ```

  这样，临界区只覆盖真正的共享内存访问；局部变量 `stat` 后续的计算不需要持锁。宏常量可以按当前配置展开为对应常量，但这与临界区放置无关。

- 不能把整个模块的函数规约集中放进一个 *_specs.h。

- 按本轮目标提取必要代码。新建切片默认一函数一文件；已有canonical文件和用户指定组织方式沿用，准确标识本轮目标函数。

如果不清楚应如何将源代码转换为可供验证的切片代码，应先查看并参考已验证函数所采用的转换方法。如果没有适用的示例，应停止并咨询人类专家以获得确认。

## QCP 工具适配

本节记录为适配 QCP 工具采用的处理方式，各条均遵循本文的用户规则优先级、
只修改验证副本及源码一致性要求，并须满足各自的适用条件。

### 1. 函数指针调用转为直接调用

当函数指针或 `done` 表项在验证覆盖的阶段内目标固定，且调用目标可由源码和配置
确定时，可在 annotated C 副本中将间接调用改为该目标函数的直接调用。固定目标
是转换依据，不能仅因为工具不支持函数指针就任意选择一个函数。

例如原始 C 中：

```c
static SemaphoreDoneType done = {
    .SemaphoreCreate = _SemaphoreCreate,
    /* ... */
};

return done.SemaphoreCreate(val);
```

若确认表项不会在该阶段被重新赋值，可在切片中写为：

```c
return _SemaphoreCreate(val);
```

转换须保留参数求值、调用顺序、返回值和目标函数的副作用；表对象及表项定位表达式
自身若有必须保留的求值或可观察行为，也不能直接丢弃。直接调用的函数仍按普通
callee 处理，使用完整契约并遵循已有验证范围；替换调用形式不赋予 trusted 身份。
记录原表项与目标函数的对应关系、配置及不变性依据，供源码一致性审查使用。

全部相关调用已转换、且表不再被验证路径读取、写入或以其他方式使用时，切片无需
再定义仅用于该分派的 `SemaphoreDoneType` 和 `done` 表；formal 定义也同步去掉
相应的 `SemaphoreDoneAbs`、stable state 中的 `semaphore_done_addr` /
`semaphore_done_abs`、`store_semaphore_done`，以及 invariant/context 中仅服务于
这张表的引用。表项与函数的对应关系保留为转换依据，不另作为运行时内存 predicate。

如果函数指针会在运行时改变、目标无法确定，或者表仍有其他被验证的用途，就不能
套用上述整体移除方案。应按实际分派行为另行建模或适配，并按本文的未覆盖情况
处理规则解决，不能静默固定目标或删除真实路径。
